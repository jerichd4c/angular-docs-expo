7. Consumo de APIs

La mayoría de las aplicaciones obtienen sus datos de un servidor a través de una API. Angular incluye su propio cliente HTTP para hacer peticiones (GET, POST, PUT, DELETE) y recibir las respuestas en formato JSON.

Configuración

Antes de hacer peticiones hay que registrar el cliente HTTP en app.config.ts. withFetch() hace que use la API fetch del navegador, recomendada cuando se usa SSR.

HttpClient: la forma clásica

El servicio HttpClient tiene un método por cada tipo de petición. Devuelve un Observable (de la librería RxJS): la petición se envía al llamar a subscribe(), que recibe la respuesta.

httpResource: la forma moderna con signals

httpResource hace la petición y expone el resultado como signals. Si la URL depende de otro signal, la petición se repite sola cada vez que ese signal cambia. No hace falta subscribe() ni ngOnInit.

Estados de una petición

Una petición tarda y puede fallar, así que la interfaz debe contemplar tres estados: cargando, error y éxito. httpResource ofrece un signal para cada uno.

Interceptores

Un interceptor es una función que se ejecuta en todas las peticiones antes de enviarlas. Se usa para agregar tokens de autenticación, registrar errores o mostrar un indicador de carga global.

Puntos clave

  • Se habilita con provideHttpClient() en app.config.ts.
  • HttpClient devuelve Observables y se usa con subscribe().
  • httpResource expone la respuesta como signals y se repite sola cuando cambian sus dependencias.
  • Toda petición tiene tres estados: cargando, error y éxito.
  • Los interceptores modifican todas las peticiones en un solo lugar.

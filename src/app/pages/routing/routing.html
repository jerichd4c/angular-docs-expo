6. Routing y navegación

El router de Angular asocia cada URL con un componente. Así una sola página HTML (una SPA) puede tener varias "pantallas" y navegar entre ellas sin recargar. Esta misma documentación funciona así: cada tema del menú es una ruta.

Definir las rutas

Las rutas se definen en app.routes.ts como una lista de objetos. Cada ruta indica un path (la URL) y el componente que se muestra. Con loadComponent, el código de cada página se descarga solo cuando se visita (lazy loading).

routerLink, routerLinkActive y router-outlet

  • routerLink: navega a otra ruta sin recargar la página.
  • routerLinkActive: agrega una clase CSS al enlace de la ruta actual.
  • <router-outlet />: el lugar donde se muestra el componente de la ruta.

Parámetros de ruta

Una ruta puede tener partes variables, marcadas con :. Por ejemplo, routing/:framework acepta /routing/angular, /routing/vue, etc. Con withComponentInputBinding(), el valor llega al componente como un input().

Navegar desde código

Además de los enlaces, se puede navegar desde la clase con el servicio Router. Es útil después de una acción: guardar un formulario, iniciar sesión, etc.

Guards: proteger rutas

Un guard es una función que decide si el usuario puede entrar a una ruta. Si no puede, se le redirige a otra (por ejemplo, al login).

Puntos clave

  • Las rutas asocian una URL con un componente y se definen en app.routes.ts.
  • routerLink navega sin recargar; <router-outlet /> muestra la página.
  • Los parámetros (:id) permiten URLs dinámicas y llegan como inputs.
  • loadComponent carga cada página solo cuando se visita.
  • Los guards controlan quién puede entrar a cada ruta.

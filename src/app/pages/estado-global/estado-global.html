8. Manejo de estado global

Algunos datos los necesitan muchos componentes a la vez: el usuario conectado, el carrito de compras, el tema claro u oscuro. En lugar de pasarlos de padre a hijo por toda la aplicación, se guardan en un servicio que cualquier componente puede usar.

El problema: prop drilling

Con input(), un dato solo puede bajar de padre a hijo. Si un componente muy profundo lo necesita, hay que pasarlo por todos los niveles intermedios, aunque no lo usen. Con un servicio, cada componente lo pide directamente.

Servicios con signals

Un servicio es una clase con el decorador @Injectable. Con providedIn: 'root', Angular crea una sola instancia para toda la aplicación (patrón singleton). Si el estado se guarda en signals, cada componente que lo use se actualiza solo.

inject(): usar el servicio

Cualquier componente obtiene el servicio con inject(). A esto se le llama inyección de dependencias: el componente no crea el servicio, Angular se lo entrega. Como todos reciben la misma instancia, todos comparten el mismo estado.

Buena práctica: estado privado y métodos públicos

En aplicaciones grandes conviene que solo el servicio pueda modificar el estado. Los componentes lo leen con asReadonly() y lo cambian a través de métodos. Así, si algo falla, se sabe exactamente dónde buscar.

NgRx: para aplicaciones grandes

NgRx es la librería de estado más usada en Angular. Su signalStore organiza el estado, los valores derivados y los métodos en una estructura estándar. Para la mayoría de proyectos, un servicio con signals es suficiente.

OpciónCuándo usarla
signal() en el componenteEl dato solo lo usa ese componente.
input() / output()El dato se comparte entre padre e hijo.
Servicio con signalsEl dato lo usan componentes lejanos o toda la app.
NgRx Signal StoreAplicaciones grandes con mucho estado y varios equipos.

Puntos clave

  • El estado global evita pasar datos por muchos niveles de componentes (prop drilling).
  • Un servicio con providedIn: 'root' tiene una sola instancia compartida por toda la app.
  • Los componentes obtienen el servicio con inject().
  • Buena práctica: estado privado, lectura con asReadonly() y cambios mediante métodos.
  • NgRx Signal Store es la alternativa para aplicaciones grandes.

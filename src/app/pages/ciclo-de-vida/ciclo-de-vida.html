5. Ciclo de vida

Cada componente pasa por etapas: se crea, se muestra, se actualiza y finalmente se destruye. Angular ofrece hooks (métodos especiales) para ejecutar código en cada uno de esos momentos.

Orden de ejecución

Angular llama a estos métodos automáticamente, siempre en este orden:

ngOnInit y ngOnDestroy: los más usados

ngOnInit se usa para inicializar: en ese momento los inputs ya tienen valor, cosa que no pasa en el constructor. ngOnDestroy se usa para limpiar. Para usarlos, la clase implementa las interfaces OnInit y OnDestroy.

afterNextRender y afterEveryRender

Se ejecutan después de que el navegador dibuja el componente. Sirven para medir elementos, usar librerías que manipulan el DOM o acceder a window y document. No se ejecutan en el servidor, así que son clave cuando se usa SSR (página 10).

¿Por qué es importante limpiar?

Si un componente inicia un intervalo y no lo detiene al destruirse, el intervalo sigue corriendo para siempre aunque el componente ya no exista. Eso es una fuga de memoria. Además de ngOnDestroy, se puede usar DestroyRef para registrar la limpieza justo donde se crea el recurso.

Demo en vivo

Puntos clave

  • Los hooks permiten ejecutar código en momentos específicos de la vida de un componente.
  • ngOnInit para inicializar (los inputs ya tienen valor); ngOnDestroy para limpiar.
  • afterNextRender se ejecuta solo en el navegador, después de dibujar.
  • No limpiar intervalos o suscripciones provoca fugas de memoria.

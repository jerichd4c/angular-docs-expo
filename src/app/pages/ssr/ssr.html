10. SSR (Server-Side Rendering)

Normalmente el navegador recibe una página vacía y Angular la dibuja con JavaScript. Con SSR, Angular se ejecuta primero en el servidor y envía la página ya dibujada. El usuario ve el contenido antes y los buscadores pueden leerlo. Esta documentación usa SSR desde que se creó con ng new --ssr.

CSR frente a SSR

La diferencia está en quién dibuja el HTML la primera vez:

BeneficioPor qué
Carga más rápidaEl contenido se ve sin esperar a que se descargue y ejecute el JavaScript.
SEOGoogle y otros buscadores reciben el texto completo de la página.
Vista previa en redesWhatsApp, X o LinkedIn pueden mostrar el título e imagen del enlace.
Dispositivos lentosEl trabajo pesado del primer dibujado lo hace el servidor.

Archivos que agrega el SSR

Con --ssr, el CLI agrega un servidor (Express) que ejecuta la misma aplicación Angular. No hay que escribir dos versiones: el mismo código corre en el servidor y en el navegador.

Modos de renderizado por ruta

En app.routes.server.ts se elige cómo se genera cada ruta. En esta documentación todo usa Prerender: el HTML se genera al compilar, porque el contenido no cambia. Por eso en la página 6 tuvimos que indicar qué parámetros prerenderizar.

Hidratación

Cuando llega el JavaScript, Angular no vuelve a dibujar la página: reutiliza el HTML que mandó el servidor y le conecta los eventos y los signals. A esto se le llama hidratación. Con withEventReplay(), si el usuario hace clic antes de que cargue el JavaScript, el clic no se pierde.

Cuidado: el servidor no es un navegador

En el servidor no existen window, document ni localStorage. El código que los use debe ejecutarse solo en el navegador, con afterNextRender (página 5) o comprobando la plataforma con isPlatformBrowser.

Demo en vivo

1. ¿Quién dibujó esta página? Recarguen (F5) estando en esta página. La primera fecha la generó el servidor y viajó dentro del HTML; la segunda es el momento en que el navegador hidrató la página.

🖥️ HTML generado en el servidor: {{ fechaServidor }} 🌐 Hidratado en el navegador: {{ fechaNavegador() ?? 'todavía no...' }}

2. Ver el HTML que envía el servidor: presionen Ctrl + U. Todo el texto de esta página aparece en el código fuente. Sin SSR, solo se vería <app-root></app-root> vacío.

3. Desactivar JavaScript: abran F12, presionen Ctrl + Shift + P, escriban Disable JavaScript y recarguen. La página se sigue viendo completa, pero las demos ya no funcionan porque no hay hidratación. Para volver, repitan con Enable JavaScript.

Ejecutar en producción

ng serve ya usa SSR durante el desarrollo. Para la versión final se compila y se ejecuta el servidor generado. Las rutas prerenderizadas también pueden publicarse como archivos estáticos.

Puntos clave

  • Con SSR, el servidor envía la página ya dibujada: carga más rápida y mejor SEO.
  • La hidratación reutiliza ese HTML y lo vuelve interactivo sin dibujarlo de nuevo.
  • Cada ruta puede ser Prerender (al compilar), Server (en cada petición) o Client (sin SSR).
  • En el servidor no hay window ni localStorage: usar afterNextRender.
  • Se activa con ng new --ssr o ng add @angular/ssr.

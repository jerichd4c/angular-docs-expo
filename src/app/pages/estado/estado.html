4. Estado y reactividad

El estado son los datos de una aplicación que cambian con el tiempo: un contador, un usuario conectado, una lista de productos. La reactividad es la capacidad de que la interfaz se actualice sola cuando ese estado cambia. Angular lo logra con signals.

¿Cómo funciona la reactividad?

Un signal es un valor que avisa cuando cambia. Cada vez que una plantilla, un computed o un effect lee un signal, Angular registra esa dependencia. Cuando el signal cambia, Angular actualiza solo lo que depende de él, sin revisar toda la página.

signal(): crear y modificar estado

Un signal guarda un valor. Se lee llamándolo como función, contador(), y se modifica con set() o update(). Con arreglos y objetos siempre se crea uno nuevo, para que Angular detecte el cambio.

computed(): valores derivados

Un computed se calcula a partir de otros signals y se actualiza automáticamente cuando alguno cambia. Es de solo lectura: no tiene set() ni update().

effect(): reaccionar a cambios

Un effect ejecuta código cada vez que cambian los signals que usa. Sirve para acciones que están fuera de la plantilla: escribir en la consola, guardar en localStorage, cambiar el título de la pestaña. Se crea dentro del constructor.

Puntos clave

  • Un signal se lee con nombre() y se modifica con set() o update().
  • computed() crea valores derivados que se actualizan solos.
  • effect() ejecuta acciones externas cuando cambian los signals.
  • Angular actualiza solo la parte de la vista que depende del signal que cambió.
